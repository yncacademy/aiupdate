05 Chat answers, agents finish

Agents: from chat to doing the work

Chat answers one question. An agent takes a multi-step job, breaks it into steps, and works through them — files, websites, schedules. It also has more ways to go wrong, so the rules matter more.

An agent is a model that can act. That is the whole promise and the whole risk. Use chat for thinking and writing; use an agent when the job has steps, files, a website or a schedule.

05.1Quick picks

JobAgent
Scheduled or repeated tasks on my own laptopOpenClaw
Many files and tasks on my computerDeepSeek Harness
Anything that needs a remote computerManus (Claude)
Daily news updates, website price tracking, Gmail suggestions, remote-computer tasksMuse (built for AI agents)
Design work at a lower price than Claude with similar quality (my test)AutoClaw by GLM
All have free use, and some need API cost. Manus daily credit is enough for quick tasks. Muse is generous with the invite plan.

05.2Why use an agent instead of chat?

  • Chat answers one question. An agent breaks a multi-step job into steps and works through them one by one.
  • Some agents can start many sub-agents to do parts of a task at the same time.
  • Use chat for thinking and writing. Use an agent when the job has steps, files, a website or a schedule.

05.3Live demos

  1. Muse: a scheduled task.

    Ask it to check a price or a news topic every day. Show that it has its own computer — you can log in, grant access, and let it do tasks like shopping. Then show where to turn the schedule off.

  2. DeepSeek Harness: everything is a plugin.

    Show a multi-file task. Explain plugins in plain words: small add-ons that give the agent new abilities.

  3. AutoClaw by GLM: same brief, different bill.

    Run the same design brief as Claude and compare. In my test GLM was cheaper with similar design quality.

05.4Agent safety rules

Say these out loud, not just in the notes. An agent with your logins is a new employee with your keys.

  1. Start with read-only access.

    Add more only when you trust the task.

  2. Never let an agent spend money without your approval.

    Set a spending limit or use a separate card.

  3. Do not connect your main email on day one.

    Test with a spare account first.

  4. Websites and emails can contain instructions that try to trick an agent.

    If an agent suddenly wants to do something you did not ask for, stop it.

  5. Keep API keys private.

    Never put them in a screenshot or a public GitHub repo.

  6. Check the first three outputs by hand.

    Only then trust the schedule.

05.5The agent brief

A good brief is mostly a list of what the agent may not do. Fill this in before you press start.

Template Agent brief 
Goal: [one sentence]
Inputs: [files, links]
Steps I expect: [1, 2, 3]
Allowed: [read files, browse]
Not allowed: [spend money, send emails, delete files]
Output: [format, where to save]
Ask me before: [anything outside the list]
Prompt injection, in one sentence

If a page or an email tells your agent to ignore your instructions, that is an attack, not a task. Stop the run, check what it read, and do not let it continue with the same access.
